# MOD0005 — A library that is not a module must not use types from a module

**Severity:** Error · **Category:** FusionModules.Design

A plain library goes wherever something that uses it goes, and the compiler makes every assembly
the library uses a dependency of its users. A library that uses a module's type therefore drags
that module into every host and every module that uses the library — the same leak as
[MOD0004](MOD0004.md), one project removed, and invisible from the host, where nothing names the
module.

Modules may use each other (a composing module joins the modules it references, and the runtime
checks those modules are activated with it), and test projects may use anything.

## Violation

```csharp
// Pricing.Shared/Quotes.cs — a plain class library
public static class Quotes
{
    public static decimal For(Order order) => order.Total * 1.2m;   // MOD0005: OrdersModule
}
```

## Fix

Move the shared type into a contracts library — no `[HostingStartup]`, referenced by the module
and by whoever needs the type — or make the library a module itself, if what it holds is
behaviour that belongs to a topology.

## How it decides

The same way as MOD0004: `GetUsedAssemblyReferences`, asked again with import tracking on and
documentation comments left out when the first answer names a module, a module behind another one
left to the one in front, and nothing reported while the compilation has compile errors.

A shared test-fixture library that is not itself a test project is a library too. If it is there
to arrange data through a module's types, say so in its project file:
`<FusionModulesProjectKind>Test</FusionModulesProjectKind>`.
