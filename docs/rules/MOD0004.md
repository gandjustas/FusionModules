# MOD0004 — The host must not use types from a module

**Severity:** Error · **Category:** FusionModules.Design

The host has no compile-time knowledge of any module. That is what lets one image serve every
deployment topology: which modules are live is decided by `HOSTINGSTARTUPASSEMBLIES` at startup,
and the host binary is identical in all of them. The moment the host names a module's type, that
module is in every deployment whether you wanted it there or not.

## What is allowed

A project reference to a module — in fact, one is required:

```xml
<ProjectReference Include="..\Modules\Orders\OrdersModule.csproj" />
```

It orders the build and copies the module's assembly next to the host so it can be loaded by
name. The rule uses `GetUsedAssemblyReferences` — the assembly references the compiler writes into
the host's output — so a reference the host never uses is invisible to it, which is exactly the
arrangement you want.

An ordinary build runs without `/doc`, and then the compiler counts an assembly as used when it
merely contributes a type to a namespace the host imports: a module with an internal class in
`Microsoft.Extensions.Hosting`, or one built with an interceptor generator. When the cheap answer
names a module, the rule asks again with import tracking on and documentation comments left out —
a `<see cref>` to a module's type, which the IDE and a build with `GenerateDocumentationFile` would
count, does not put the module in a deployment — so only real use is reported.

The compiler also counts every assembly a used assembly references. A module the host reaches only
through a plain library it uses is reported in that library's own build, as [MOD0005](MOD0005.md):
that is where the line to change is. A module behind another module the host uses is not named
either: the one in front is, and removing that use removes both.

Compiler warnings promoted by `TreatWarningsAsErrors` do not stop the check; real compile errors
do, because then the compiler cannot tell which references are used.

Do **not** try to harden this with `ReferenceOutputAssembly="false"`. The analyzer tolerates it,
and the module then stops being copied to the output at all — so nothing loads, and the failure
presents as a routing problem. The analyzer is the enforcement mechanism, not MSBuild.

## Violation

```csharp
// Host/Program.cs
var report = new OrderReport();   // MOD0004: OrdersModule
```

## Fix

Move the shared type into a contracts library: a plain `Microsoft.NET.Sdk` project with no
`[HostingStartup]`, referenced by the host and by the module. A contracts library is not a
module, so [MOD0001](MOD0001.md) does not apply to it and its types are meant to be public.

If what the host needs is behaviour rather than a type, then it does not need this at all — put
the behaviour in a module. A host that has to do something in every topology is a module too: the
entry assembly can carry `[assembly: HostingStartup]` like any other, and ASP.NET Core activates
it first.
