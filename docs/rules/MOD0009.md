# MOD0009 — A hub's client interface must be reachable from SignalR's generated proxy

**Severity:** Error · **Category:** Modulith.Design

A `Hub<TClient>` does not call your client interface. SignalR generates an implementation of it at
runtime, with `TypedClientBuilder`, into a dynamic assembly of its own — and a type there cannot
implement an `internal` interface declared in yours.

So the rule you are otherwise following, [MOD0001](MOD0001.md), points the wrong way for exactly
this one type. Make the interface internal and the project compiles, no diagnostic fires, and every
test that never starts a hub passes. What fails is the running process, on the first resolve of
`IHubContext<THub, TClient>`:

```
System.TypeLoadException: Type 'Microsoft.AspNetCore.SignalR.TypedClientBuilder.IPaymentClientImpl'
from assembly 'Microsoft.AspNetCore.SignalR.TypedClientBuilder, Version=0.0.0.0, Culture=neutral,
PublicKeyToken=null' is attempting to implement an inaccessible interface.
```

That is the first time a real client connects, which in a migration is the first time you start the
merged host — long after the build, the tests and the route inventory have all agreed the move was
clean.

## Violation

```csharp
interface IPaymentClient                       // MOD0009
{
    Task Paid(string reference);
}

sealed class PaymentHub : Hub<IPaymentClient> { }
```

## Fix

Let the proxy see your internals. The dynamic assembly is built with `AssemblyBuilderAccess.Run`
and is therefore unsigned, so its name is all it takes:

```csharp
[assembly: InternalsVisibleTo("Microsoft.AspNetCore.SignalR.TypedClientBuilder")]
```

One line, and the module's surface stays exactly as MOD0001 wants it — the interface and every
type in its signatures remain internal. This is the fix to reach for, and the rule goes quiet once
the attribute is there. It is unavailable to a strong-named module: naming an unsigned friend from
a signed assembly is CS1726.

The alternative is to make the interface public:

```csharp
public interface IPaymentClient
{
    Task Paid(string reference);
}
```

Expect that to spread. A public interface member cannot take or return a less accessible type, so
the compiler walks you through the interface's whole signature closure with CS0050 and CS0051, and
each type it names goes public too. Stop the closure where you can — a factory method on a payload
does not have to travel with it.

It spreads outwards as well as inwards. An interface nested in an internal type is invisible outside
the assembly however public it is declared, so the rule reports it and the fix takes the containing
type public too — at which point [MOD0001](MOD0001.md) has a question about the container, which is
a different type and a real decision. The one-line fix costs none of that.

## Why this is not an `.editorconfig` entry

MOD0001's escape hatch records a decision: this type is public and I meant it. For a hub client
there is no decision to record — the runtime requires it, and writing the name down says only that
you met the requirement. So the interface, and the hub itself, are exempt from MOD0001
automatically; what remains is whether the proxy can reach them, which is what this rule asks.

A controller is the opposite case and worth contrasting: internal is achievable there, so a public
one is a choice. See [MOD0001](MOD0001.md).

## When the rule is wrong

A client interface declared in a contracts library that both the hub and its callers reference is
already public, and nothing here fires. The rule only ever looks at interfaces declared in the
module itself, because those are the only ones it could ask you to change.
