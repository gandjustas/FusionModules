# MOD0009 — A module must not register itself as a startup filter

**Severity:** Error · **Category:** FusionModules.Design · **Code fix:** yes

`ModuleBase` registers the module as an `IStartupFilter` for you. Registering it again means
`Configure` runs twice: every piece of middleware the module adds is added twice, and every
endpoint it maps is mapped twice — which throws at startup.

Only the module itself counts: `AddSingleton<IStartupFilter>(this)`,
`AddSingleton<IStartupFilter>(new Module())` or `AddSingleton<IStartupFilter, Module>()`. A module
that registers some other startup filter of its own is doing something ordinary.

## Violation

```csharp
sealed class Module : ModuleBase
{
    protected override void ConfigureServices(IHostApplicationBuilder builder)
    {
        builder.Services.AddSingleton<IStartupFilter>(this);   // MOD0009 — ModuleBase already did this
        builder.Services.AddControllersWithViews().AddApplicationPart(typeof(Module).Assembly);
    }
}
```

## Fix

Delete the registration. The code fix does it: a statement goes whole, and a call in a chain
leaves the rest of the chain on its receiver.

## Where it comes from

Hand-written modules that predate `ModuleBase` did this themselves, and the line survives the
conversion because it looks load-bearing. It was, once. [MOD0002](MOD0002.md)'s fix drops it when
it converts such a module.
