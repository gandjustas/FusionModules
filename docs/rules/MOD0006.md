# MOD0006 — The host's builder does not load modules

**Severity:** Error · **Category:** FusionModules.Design · **Code fix:** yes

Modules are hosting startups, and only ASP.NET Core's `GenericWebHostBuilder` runs hosting
startups. `WebApplication.CreateBuilder` uses it. `WebApplication.CreateSlimBuilder` and
`WebApplication.CreateEmptyBuilder` configure their web host through `SlimWebHostBuilder`
instead, which reads `HOSTINGSTARTUPASSEMBLIES` and then ignores it.

A host built that way loads no module in any topology. Nothing fails and nothing is logged: the
application starts with the host's own endpoints and none of the modules', and
[`ValidateModules()`](MOD0011.md) would report every module as not started.

## Violation

```csharp
var builder = WebApplication.CreateSlimBuilder(args);   // MOD0006
```

```csharp
var builder = WebApplication.CreateEmptyBuilder(new WebApplicationOptions { Args = args });   // MOD0006
```

## Fix

Use `WebApplication.CreateBuilder`. It has the same overloads — no arguments, `string[] args`,
`WebApplicationOptions` — so the code fix changes the name and nothing else:

```csharp
var builder = WebApplication.CreateBuilder(args);
```

What the slim and empty builders leave out is then back: configuration from environment
variables with the `ASPNETCORE_` prefix, the default logging providers, IIS integration and the
rest of `CreateBuilder`'s defaults. If the host was slim for start-up time or for trimming, those
are the costs of loading modules at all.

## When it is reported

In a project MSBuild classifies as a host — or a program, without the package's targets — that
references the FusionModules runtime. A test project may build a slim host on purpose, and a
library builds none of its own, so neither is reported.
