# MOD0003 — The host must not use types from a module

**Severity:** Error · **Category:** Modulith.Design

The host has no compile-time knowledge of any module. That is what lets one image serve every
deployment topology: which modules are live is decided by `HOSTINGSTARTUPASSEMBLIES` at startup,
and the host binary is identical in all of them. The moment the host names a module's type, that
module is in every deployment whether you wanted it there or not.

## What is allowed

A project reference to a module — in fact, one is required:

```xml
<ModulithModule Include="..\Modules\Orders\OrdersModule.csproj" />
```

It orders the build and copies the module's assembly next to the host so it can be loaded by
name. The rule uses `GetUsedAssemblyReferences`, so a reference the host never uses is invisible
to it, which is exactly the arrangement you want.

Do **not** try to harden this with `ReferenceOutputAssembly="false"`. The analyzer tolerates it,
and the module then stops being copied to the output at all — so nothing loads, and the failure
presents as a routing problem. The analyzer is the enforcement mechanism, not MSBuild.

## Violation

```csharp
// Host/Program.cs
var report = new OrderReport();   // MOD0003: OrdersModule
```

## Fix

Move the shared type into a contracts library: a plain `Microsoft.NET.Sdk` project with no
`[HostingStartup]`, referenced by the host and by the module. A contracts library is not a
module, so [MOD0001](MOD0001.md) does not apply to it and its types are meant to be public.

If what the host needs is behaviour rather than a type, then it does not need this at all — put
the behaviour in a module. A host that has to do something in every topology is a module too: the
entry assembly can carry `[assembly: HostingStartup]` like any other, and ASP.NET Core activates
it first.
