# MOD0008 — A hosted service in a module runs in every replica that loads it

**Severity:** Warning · **Category:** FusionModules.Usage

A background worker that ran in one replica of one service now runs wherever its module is
loaded. If two replicas of a topology both load that module, it runs twice. If three topologies
include it, it runs in all of them.

That is a change in behaviour, it is invisible in the diff, and it shows up in production.

## Violation

```csharp
sealed class Module : ModuleBase
{
    protected override void ConfigureServices(WebHostBuilderContext context, IServiceCollection services) =>
        services.AddHostedService<NightlyReconciliation>();   // MOD0008
}
```

## The question to answer

Not "how do I silence this" but "how many times should this run".

| | |
|---|---|
| **Leader election** | The work is idempotent-ish and you want it once per cluster. A distributed lock, a database advisory lock, or whatever the platform provides. |
| **A worker topology** | One deployment loads this module and nothing else loads it. The clearest answer when the work is substantial, and it makes scheduling a deployment concern rather than a code one. |
| **Once per replica is correct** | Cache warming, metric collection, local cleanup. Fine as it is. |
| **Leave it outside** | Some work does not belong in a web host at all, and merging the services is a good moment to notice. |

## Suppression

Once you have decided, say which decision it was:

```csharp
// One per replica is intended: this warms a per-process cache.
#pragma warning disable MOD0008
services.AddHostedService<CacheWarmer>();
#pragma warning restore MOD0008
```

Or, if every hosted service in the solution has been considered:

```ini
# .editorconfig
dotnet_diagnostic.MOD0008.severity = none
```

The rule's value is in being answered once per hosted service, not in staying on forever.
