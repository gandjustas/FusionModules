# MOD0002 — The type named by HostingStartup must be a module

**Severity:** Error · **Category:** FusionModules.Design · **Code fix:** yes

ASP.NET Core instantiates the type named in `[assembly: HostingStartup(typeof(X))]` and casts it
to `IHostingStartup`. If the cast fails the application dies at startup with a message about a
type most readers have never heard of.

Deriving from `ModuleBase` is also what gives the module its entry in the configuration registry
of activated modules, and its check that the modules it references were activated too.

## Violation

```csharp
[assembly: HostingStartup(typeof(Module))]   // MOD0002

class Module { }
```

## Fix

```csharp
class Module : ModuleBase { }
```

The code fix does it for a hand-written `IHostingStartup`. `IHostingStartup` in the base list
becomes `ModuleBase`, and a `Configure(IWebHostBuilder)` that only calls
`builder.ConfigureServices(...)` becomes `ConfigureServices(IHostApplicationBuilder)`: the lambdas'
bodies move in, `services` becomes `builder.Services`, `context.Configuration`
`builder.Configuration` and `context.HostingEnvironment` `builder.Environment`.

`ModuleBase` registers the module as an `IStartupFilter` itself, so the fix drops a registration
of the module as one, and turns an `IStartupFilter` implementation of the usual shape — `next(app)`,
then the module's middleware — into an override of `Configure(IApplicationBuilder)`. The interfaces
leave the base list rather than staying next to `ModuleBase`: re-implementing either would bypass
`ModuleBase`'s own implementation, which is what registers and validates the module.

Other calls on the web host builder, a filter that does its work before `next`, another member
named `Configure` or `ConfigureServices`, or a `return` in any but the last of several
`ConfigureServices` lambdas have no direct counterpart; the fix is not offered then, and the
conversion is yours to write. Locals of the same name in two lambdas each keep a block of their own.

An indirect base is fine — a shared `CompanyModule : ModuleBase` carrying your own conventions is
a good idea once you have more than a handful of modules.
