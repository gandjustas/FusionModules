# MOD0004 — The host must not declare an ApplicationPart for a module

**Severity:** Error · **Category:** FusionModules.Design

Application Part Discovery and HostingStartup do not know about each other.

At build time the Razor SDK emits `[assembly: ApplicationPart("X")]` on a project for every
project reference that itself references `Microsoft.AspNetCore.Mvc.*`. At runtime
`AddControllers` / `AddRazorPages` / `AddMvc` read those attributes and load the named assemblies
as application parts.

So the host picks up a module's controllers and pages **without ever running the module's code**.
The endpoints appear; the services they depend on do not. And they appear in every topology,
including the ones that deliberately left that module out.

## Fix

Set the property on the host project:

```xml
<GenerateMvcApplicationPartsAssemblyAttributes>false</GenerateMvcApplicationPartsAssemblyAttributes>
```

The FusionModules MSBuild assets do this for you once the project is detected as a host. Set
`FusionModulesConfigureMvcApplicationParts` to `false` to opt out.

Then let each module add itself, inside its own `ConfigureServices`, where it also registers
everything its controllers need:

```csharp
protected override void ConfigureServices(WebHostBuilderContext context, IServiceCollection services) =>
    services.AddControllersWithViews().AddApplicationPart(typeof(Module).Assembly);
```
